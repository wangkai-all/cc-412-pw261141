# 指标突变归因工作台

指标突变后，把**上游数据缺口、口径变更、业务结构变化**三类候选解释分开举证、分开比较，
而不是按相关系数给一句"原因"。全部数据为虚构，全部分解为确定性计算、逐步可复核，
不调用任何外部模型，所有输出均为**候选解释（未证实）**并附"无法排除的可能"。

## 运行

```bash
python3 -m server.app        # 默认 8412 端口，首次启动自动建库、生成虚构数据、跑初始分析
# 打开 http://127.0.0.1:8412
python3 -m unittest discover -s tests -v   # 10 项核心行为测试
```

仅依赖 Python 3.11 标准库（sqlite3 + http.server），前端为无构建的静态页面。

## 虚构场景

电商「星澜商城」下单转化率（支付订单/会话），按 app / web / 小程序三渠道，60 天。
2026-10-17 指标骤降约 1.1pp，数据中埋了三类相互独立的结构（生成器知道真相，
分析代码只看证据）：

| 埋藏结构 | 时间 | 内容 |
|---|---|---|
| 上游数据缺口 | 10-17 ~ 10-19 | web 渠道批次只到 45%（其余在"待重传"中，可在网页补齐） |
| 口径变更 | 10-17 起 | 订单口径 v1（含24h内取消）→ v2（剔除24h内取消），可在网页撤回 |
| 业务结构变化 | 10-10 起 | 小程序会话占比持续爬升（其转化率偏低），拉低整体 |

## 三个服务如何协作

```
接入日志服务          依赖追踪器              归因报告服务
ingest_log ──┐      definition_versions ──┐
batches      ─┼──▶  caliber_events       ─┼──▶  钉住同一输入版本（清单+水位）
pending_…    ─┘      镜头→存储依赖图      ─┘    三个镜头各自重算 → 缓存 → 报告
```

- **输入版本**：每次分析钉住一份清单（批次集合 + 接入日志水位 + 口径事件水位 +
  解析后的口径时间线），三个镜头在同一版本上重算对照。所有证据表**只增不改**，
  因此任何历史版本都可精确重放。
- **依赖追踪器**维护「镜头 → 数据存储」依赖图：修订（补齐/撤回）触碰哪些存储，
  与镜头依赖求交，得到**受影响比较**——只有它们需要重算。

## 缓存权衡：全量保存 vs 按需重算

两者各有代价：保存全部中间对照占存储、且修订后大量条目作废；完全按需重算则
每次打开报告都要付计算延迟。本方案折中：

- **持久化**：原始证据（批次/日志/事件，只增）、最终报告（小 JSON）。
- **缓存**：镜头级对照结果，键 = `(镜头, 输入版本, 代码版本, 参数)`。
- **防过期证据的机制保证**：修订产生新输入版本 → 受影响镜头的旧缓存键
  **永远不会再被命中**（查询总是钉在当前版本），旧条目保留仅供审计，
  界面标注"历史·不可命中"。这不是约定，是键结构决定的。
- **依赖未变的镜头**经依赖追踪器证明后沿用旧结果，缓存行的 `source_version_id`
  如实记录实际计算版本，界面标注"依赖未变·沿用旧版"。
- 同一版本上再次重跑 → 全部缓存命中（网页任务步骤里可见三种来源：
  本次重算 / 缓存命中 / 沿用旧版）。

## 网页操作

- **补齐缺口**：把上游重传记录追加为 redelivery 批次（证据只增），产生新输入版本，
  三个镜头全部重算。
- **撤回口径变更**：追加 retract 事件（不修改历史），产生新输入版本；
  受影响 = 口径 + 结构镜头，缺口镜头依赖未变而沿用。
- **重跑受影响比较**：任务按步骤执行（钉版本 → 逐镜头 → 汇总），每步落检查点。
- **中断后继续**：运行中可"中断"（步骤边界生效）；进程被杀后重启，
  遗留 running 任务自动标记为"已中断"，点"继续"从断点续跑，已完成步骤不重做。

## 三个镜头的方法与纪律

1. **上游数据缺口**：接入日志期望 vs 实到 → 缺失会话；按同来源同窗口已送达记录的
   转化率（v1 原始口径，完整性估计与口径定义无关）折算缺失订单，构造"若补齐"反事实。
2. **口径变更**：同一输入版本上按 v1/v2 **双跑**，差值即定义本身的影响；
   前窗口两口径应接近，作为对照 sanity check。
3. **业务结构变化**：精确三项分解 ΔR = Σw₀Δr（水平）+ Σr₀Δw（结构）+ ΣΔwΔr（交互），
   恒等闭合（报告附恒等式残差，测试断言其为 0）；另给出**调整后视图**——
   剔除已估计的缺口与口径影响后的剩余结构。

每个候选都列出：方法、前提假设、可展开的证据表、**无法排除的可能**。
三个候选独立估计、**不可相加**（缺口与口径的影响也会体现在结构分解的水平项里），
报告与页面均明示这一点。措辞纪律：只说"证据支持/弱支持/未获支持"，
从不说"原因已确认"。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/overview` | 序列、异常、缺口、口径事件、任务、缓存、版本 |
| GET | `/api/anomalies/{id}/report` | 最新归因报告（候选+证据+无法排除） |
| POST | `/api/anomalies/{id}/rerun` | 当前输入版本重跑全部镜头 |
| POST | `/api/gaps/backfill` | `{source,day}` 或 `{all:true}`，补齐缺口 |
| POST | `/api/caliber/retract` | `{event_id}`，撤回一次口径变更 |
| POST | `/api/jobs/{id}/interrupt` | 中断任务（步骤边界生效） |
| POST | `/api/jobs/{id}/resume` | 从断点继续 |
